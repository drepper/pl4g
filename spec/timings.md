Compiler Timings
================

How long the compiler takes on each sample program, in milliseconds, the
best of five runs.  One row per commit and one column per program: the
commits go on for ever, so the tables grow down rather than across, and
the programs are split into groups by what would move them.  A blank
means the sample did not exist yet at that commit.

A table is at most fifteen columns wide, counting the one that names the
commit; a group with more programs than that is written as several,
numbered.  Samples are never removed, so every group reaches that width
in the end -- and a column nobody can see beside the commit it belongs to
is a column nobody can read.

Measured on one machine, so the numbers are worth comparing with each
other and with nobody else's.  A hash ending in `+` was measured with
changes not yet committed.  Written by `bin/pl4g-timing`.

Work
----

The sum of the compiler's own stages, which is what a change to the
compiler moves.
