title: Names and keywords

Part of [[lexical]].

**An identifier** begins with a letter or `_` and goes on with letters, digits
and `_` -- any Unicode letter, but no raised digit, so `a²` is a square and
not a name.  Case matters.  A definition's name may be a path into a type,
`Walk.next` ([[functions.define]]).

**Keywords** cannot be names:

    fn  return  yield  let  mut  singleton  unit  type  enum  bundle  macro
    pre  post  if  elif  else  match  while  unless  foreach  break
    continue  defer  comptime  in  true  false  and  or

**`_`** is the name that is not one: the wildcard arm of a `match`, a loop
value that is not wanted, and the place `_ ← f()` drops a value into.

**A name with `'` after it is a type parameter**, `T'`, declared by being used
([[types.generic]]).

**A name beginning with `⎕` belongs to the compiler** (U+2395, APL's quad):
`⎕heap`, `⎕narrow`, `⎕import`.  A program may use the ones there are and may
not define one (4219), so a new one never takes a name away from a program.
One may carry a key after `@`: `⎕sc@write` is one name, the system call's
number.  All of them are listed in [[builtins]].

**Marks that make a name something else**, each written right before it:

    §rows        a label for a loop                    [[statements.jumps]]
    ¤meter       a unit                                [[types.units]]
    ⧖a           a lifetime                            [[memory.lifetimes]]
    $x           a hole in a macro's pattern           [[compiletime.macros]]
    `+`          an operator named as a function       [[functions.operators]]
    .name ← v    an argument or a field given by name  [[expressions.calls]]

**`@[` begins an attribute list**, `@[startup, impure]`, written before what
it is about: [[attributes]].

A name means what the nearest definition of it means.  A module's names are
reached through the name it was imported as, `std.text` ([[modules]]); a
macro's own names are renamed so they cannot meet the caller's
([[compiletime.macros]]).
