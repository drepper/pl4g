tree-sitter-pl4g
================

The [tree-sitter](https://tree-sitter.github.io/) grammar for PL4G, which is
what an editor, a syntax highlighter or anything else that wants to read the
language without running the compiler uses.

It is a second statement of what a program is, and two statements of one thing
can disagree.  What keeps them together is a test: for every program in the
language test suite, the grammar and the compiler must agree on whether it
parses -- in both directions, so a grammar that is too loose fails as surely as
one that is too strict.  That test lives in `tests/compiler/test_grammar.py` and
runs with the rest of the suite.

**A change to the syntax changes this grammar in the same commit.**  There is no
mechanism that could make that automatic, so it is a rule instead, and the test
is what notices when the rule was not followed.

Layout
------

The language delimits a block either by indentation or by braces, and no
context-free grammar can express indentation.  The tokens that stand for it come
from the external scanner in `src/scanner.c`: it gives out a newline where one
ends a statement, and an indent or a dedent where the column changes.  It also
knows about comments, because a line holding nothing but a comment ends no
statement and says nothing about the column a block is measured against.

Layout of this directory
------------------------

| Path | What it is |
|---|---|
| `grammar.js` | the grammar, which is the thing to edit |
| `src/scanner.c` | the external scanner, for the layout tokens |
| `src/parser.c`, `src/node-types.json` | generated by `tree-sitter generate`, committed so that a reader needs no tools |
| `queries/highlights.scm` | what to colour, using tree-sitter's own capture names |
| `test/corpus/` | the grammar's own tests, run by `tree-sitter test` |

Using it
--------

```sh
tree-sitter generate       # after editing grammar.js; the result is committed
tree-sitter test           # the corpus above
tree-sitter parse FILE     # one program, as a tree
tree-sitter highlight FILE # one program, coloured
```

`bin/pl4g-decisions` builds the grammar into a shared library on demand and uses
these same queries, so what it colours and what an editor colours cannot drift.
